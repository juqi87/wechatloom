# WeChatLoom 1.0.0

WeChatLoom 1.0.0 is the first stable release of the local Markdown-to-WeChat workflow and its guarded Official Account draft pipeline. Its real-draft and human visual acceptance gates were signed off before tagging.

## Highlights

- Deterministic mobile-first HTML with 24 bundled themes and 24 strict components.
- Local preview plus 320, 375, and 430 px PNG review snapshots.
- Safe local and remote image materialization, formula rendering, and a constrained Mermaid subset.
- Named Official Account verification without exposing credentials or access tokens.
- Draft add and update through a persisted dry-run plan, expiring confirmation token, duplicate prevention, and recoverable unknown-outcome state.
- Stable JSON protocol envelope version 1.0.
- Standalone macOS and Linux binaries for amd64 and arm64, plus Windows amd64.
- SHA-256 verification, CycloneDX/SPDX release SBOMs, and keyless Sigstore signing of release checksums.
- Private credential-file enforcement through Unix mode checks and Windows ACL validation. Windows permits only the current user plus the operating system's privileged `SYSTEM` and built-in `Administrators` principals.

## Upgrade and compatibility

The release binary reports `1.0.0`. GoReleaser also injects the tag version at build time. Existing v0.2 project configuration, themes, components, and build inputs remain data-compatible; the public JSON envelope remains at schema version `1.0`.

The bundled Codex Skill reports source version `1.0.0`. Updating an already installed Skill remains an explicit local configuration write:

```bash
wechatloom skill status codex --json
wechatloom skill update codex --json
```

## Release verification

Installers download only from `juqi87/wechatloom`, verify the selected standalone binary against `SHA256SUMS`, and refuse mismatches. The checksum file is accompanied by `SHA256SUMS.sigstore.json` for keyless Sigstore verification.

No command creates or updates a WeChat draft without a fresh persisted plan and an explicit confirmation command.

See the [1.0.0 acceptance record](v1.0.0-acceptance.md) for completed and pending release gates.
